# Accessibility and AI-era UX baseline

Target: WCAG 2.2 AA for the production site, subject to formal testing before launch.

The starter includes semantic headings, skip navigation, keyboard-operable navigation, visible focus treatments, labelled forms, status announcements, reduced-motion support, responsive layouts and no essential interaction that depends on colour alone.

The information architecture also separates three questions:
1. Accessibility — can the visitor use the experience?
2. Usability — can the visitor understand it?
3. Intent-led UX — can the visitor reach the answer/action quickly?

The homepage therefore provides both conventional navigation and a “What are you trying to achieve?” route. Navigation is configuration-driven so real analytics and user research can justify changing labels, order or prominence later.

Before launch, run keyboard-only testing, screen-reader spot checks, zoom/reflow testing, contrast checks, form error testing and an automated accessibility scan. Automated checks are not a substitute for human testing.
