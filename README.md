# ZenAI Digital Website V2

A maintainable, research-led website starter for **ZenAI Digital** built for GitHub + Cloudflare Workers + Static Assets.

## Core proposition

**From Strategic Intent to Intelligent Execution**

**AI transformation is enterprise transformation.**

**Assess comprehensively → Identify the constraint → Architect the target → Build the capability → Transform systematically → Measure and evolve.**

## What changed in V2

- Intent-led homepage: visitors can navigate by what they are trying to achieve.
- Configurable navigation tabs in `src/content/site.json`.
- Course/capability-program lifecycle: `draft`, `published`, `archived`.
- “Capability Building” replaces training-led positioning.
- Enterprise AI Transformation Capability model with 10 interconnected domains.
- Lightweight browser-only capability self-check; responses are not transmitted or stored.
- Transformation constraint/bottleneck concept integrated with the assessment pathway.
- Research/evidence layer linking to UTS, Google Scholar, LinkedIn, CloudTechInfo, YouTube and supplied book links.
- Clear distinction between the historical CCMM research foundation and the new AI-era ZenAI extension.
- SEO + AI-discovery outputs: static HTML, sitemap, robots, RSS, JSON-LD and `llms.txt`.
- Accessibility/UX baseline and intent-led navigation.
- Simple contact workflow: Contact page -> visitor email application -> info@cloudtechinfo.com.
- Redirect pages for the old `/method/`, `/tools/` and `/learning/` paths.

## Local -> GitHub -> Cloudflare workflow

Use this as the normal maintenance path:

```text
Windows local project
      ↓
Edit content/source
      ↓
npm run build
      ↓
GitHub Desktop: Commit
      ↓
GitHub Desktop: Push origin
      ↓
GitHub.com repository
      ↓
Cloudflare Workers Builds
      ↓
Live website
```

Do not manually upload each future website change to Cloudflare.

## Build

Requires Node.js.

```bash
npm install
npm run build
```

The build script recreates `public/` from `static/` and the structured content files.

For local Worker development:

```bash
npm run dev
```

For a manual Wrangler deployment:

```bash
npm run deploy
```

When Git integration is enabled in Cloudflare, routine production deployment should come from GitHub rather than manual deployment.

## Content maintenance

See `docs/CONTENT-MANAGEMENT.md`.

The most important controls are:

### Navigation
`src/content/site.json` -> `nav`

Use `enabled` and `order` to hide/show/reorder tabs.

### Capability programs/courses
`src/content/courses.json`

- `draft`: not generated publicly
- `published`: generated and included in sitemap/schema
- `archived`: retained in source but not public

This makes adding, updating or retiring an offering a content operation rather than a site redesign.

## Contact

The current release uses a deliberately basic email contact approach.

- The Contact page displays `info@cloudtechinfo.com`.
- The **Email ZenAI Digital** button opens the visitor's email application using a `mailto:` link.
- The email subject is prefilled as `ZenAI Digital Enquiry`.
- There is no Web3Forms, D1, Resend, Apps Script or verification-token workflow in this version.
- Visitors may include a phone number in their email if they want a callback; it is not required.

This keeps the initial production site simple and dependable. A managed web form can be added later if enquiry volume justifies it.
